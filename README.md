# BarBot

BarBot — Telegram-справочник для сотрудников бара. Категории и позиции
полностью формируются из `data/catalog.json`: новую категорию, напиток,
десерт или рабочий стандарт можно добавить без изменения Python-кода.

Текущая версия использует Python 3.12, aiogram 3 и Telegram long polling.
Каталог остаётся локальным, read-only и валидируется Pydantic при каждом
обращении.

## Возможности

- главное inline-меню: «📚 Каталог» и «🔍 Поиск»;
- динамические категории, подкатегории и позиции;
- один необязательный уровень подкатегорий с сортировкой и `is_active`;
- пагинация по 8 элементов;
- универсальные карточки с составом, характеристиками, шагами и тегами;
- отправка фотографии по Telegram `file_id`;
- поиск по названию, описаниям, тегам и ингредиентам;
- FSM-диалог поиска с командой `/cancel` и inline-отменой;
- понятные сообщения при ошибках файла или структуры каталога.

## Архитектура

```text
data/catalog.json
       ↓
app/storage/        чтение JSON и валидация
       ↓
app/models/         Pydantic-модели
       ↓
app/services/       каталог и поиск без Telegram
       ↓
app/handlers/       координация Telegram-сценариев
       ↓
app/keyboards/      только построение inline-кнопок
```

Основные каталоги:

- `app/models/` — каталог, категории, подкатегории, позиции и ингредиенты;
- `app/storage/` — безопасное read-only JSON-хранилище;
- `app/services/` — бизнес-логика каталога и поиска;
- `app/handlers/` — `/start`, каталог, карточки и FSM-поиск;
- `app/keyboards/` — callback-фабрики и inline-клавиатуры;
- `app/utils/` — нормализация и безопасное HTML-форматирование;
- `data/catalog.json` — данные каталога;
- `tests/` — тесты без обращений к Telegram API.

`app/handlers/admin.py` и `data/users.json` на этом этапе не используются.

## Создание Telegram-бота

1. Откройте официальный аккаунт `@BotFather` в Telegram.
2. Выполните команду `/newbot`.
3. Укажите отображаемое имя и уникальное имя, оканчивающееся на `bot`.
4. Сохраните выданный токен. Не публикуйте его и не добавляйте в Git.

## Установка

```bash
cd /opt/barbot
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Настройка `.env`

Скопируйте безопасный пример:

```bash
cp .env.example .env
```

Заполните значения:

```dotenv
BOT_TOKEN=replace_with_your_telegram_bot_token
CATALOG_PATH=data/catalog.json
```

- `BOT_TOKEN` обязателен.
- `CATALOG_PATH` необязателен и по умолчанию указывает на
  `/opt/barbot/data/catalog.json`.
- Относительный `CATALOG_PATH` всегда вычисляется от корня проекта, поэтому
  запуск не зависит от текущей рабочей директории.

Настоящий `.env` исключён из Git.

## Запуск

Активируйте виртуальное окружение и запустите:

```bash
source .venv/bin/activate
python -m app.bot
```

При запуске бот отключает webhook без удаления накопившихся обновлений и
переходит в long polling.

## Формат `catalog.json`

Категория может содержать `items` непосредственно или использовать один
уровень `subcategories`. Названия разделов не прописываются в handlers или
клавиатурах.

```json
{
  "version": 1,
  "categories": [
    {
      "id": "coffee",
      "name": "Кофе",
      "emoji": "☕",
      "description": "Кофейная карта",
      "sort_order": 20,
      "is_active": true,
      "subcategories": [
        {
          "id": "hot-coffee",
          "name": "Горячий кофе",
          "emoji": "🔥",
          "description": null,
          "sort_order": 10,
          "is_active": true,
          "items": [
            {
              "id": "flat-white",
              "name": "Флэт уайт",
              "description": "Кофейный напиток с молоком",
              "photo_file_id": null,
              "ingredients": [
                {
                  "name": "Эспрессо",
                  "amount": 36,
                  "unit": "г"
                }
              ],
              "fields": {
                "cup": "200 мл",
                "coffee_weight": "18 г",
                "temperature": "65 °C"
              },
              "steps": [],
              "tags": [
                "кофейный"
              ],
              "sort_order": 10,
              "is_active": true
            }
          ]
        }
      ],
      "items": []
    }
  ]
}
```

Поле `subcategories` необязательно и по умолчанию пустое. Благодаря этому
старый формат с позициями непосредственно в `category.items` продолжает
работать.

`id` категории, подкатегории и позиции используются вместе в callback-данных.
Для гарантированного соблюдения лимита Telegram они должны:

- начинаться со строчной латинской буквы или цифры;
- содержать только `a-z`, `0-9`, `_` и `-`;
- иметь длину не более 18 символов;
- быть уникальными.

`sort_order` задаёт порядок. Записи с `is_active: false` не отображаются и не
участвуют в поиске. `fields` — произвольный JSON-объект для специфичных
характеристик любой категории.

Текущий каталог содержит одну основную категорию «Коктейли» и четыре
подкатегории: фирменные, классические, безалкогольные и методы приготовления.
Все 24 технологические карты импортированы из `source/tech_cards.txt`.
Неоднозначности исходника перечислены в `source/import_warnings.md`.

### `photo_file_id`

`photo_file_id` — идентификатор уже загруженной в Telegram фотографии, а не
локальный путь или URL. Если поле заполнено, бот отправляет фото и использует
карточку как caption, когда она помещается в лимит Telegram. Длинная карточка
отправляется отдельным сообщением. При недействительном `file_id` бот пишет
техническую ошибку в лог и показывает текстовую карточку.

Чтобы получить `file_id`, фотографию нужно один раз отправить Telegram-боту и
сохранить `file_id` из объекта сообщения.

## Тесты и статические проверки

Тесты не подключаются к Telegram API:

```bash
source .venv/bin/activate
python -m pytest
python -m compileall app
git diff --check
python -c "from app.bot import main; print('Import OK')"
```

## Ограничения read-only версии

- бот не записывает и не редактирует JSON;
- нет админки, избранного и статистики;
- `data/users.json` не используется;
- нет базы данных, Redis, webhook или web-панели;
- после ручного изменения `catalog.json` данные перечитываются при следующем
  действии пользователя;
- поддерживается ровно один уровень подкатегорий;
- при синтаксической ошибке или невалидной структуре каталог временно
  недоступен до исправления файла.
