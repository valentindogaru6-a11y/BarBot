# Global KOS Structure

## Universal Layers

`00-governing`

- workflow
- memory policy
- trust levels
- semantic compression
- knowledge evolution
- staleness review

`01-canonical`

- summary
- decisions
- patterns
- lessons
- compressed
- reference

`02-working`

- current context
- discovery inbox
- optional task-level memory utility pilot log
- confirmed facts
- hypotheses
- dead ends
- open questions

`03-localization`

- graph or index workflow
- freshness manifest
- query playbook

Optional support files, when they reduce future work

- `MEMORY_INDEX.md`
- `MEMORY_USAGE_REGISTRY.md`
- `MEMORY_HEALTH.md`
- `archive/`

## Global vs Local Split

Global KOS owns:

- method rules
- lifecycle states
- trust model
- importance model
- pruning and compression rules
- knowledge extraction protocol
- token economy rules
- reusable templates

Local project memory owns:

- summaries of the actual project
- project decisions
- project patterns
- project lessons
- symbol cards
- feature notes
- reference docs
- freshness entries tied to project files or graph slices

## Non-Negotiable Rule

Every project must have local memory. No project should write its facts into the global methodology.
