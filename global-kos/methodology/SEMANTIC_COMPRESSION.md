# Semantic Compression

## Purpose

Reduce memory size without losing meaning.

## Compression Ladder

`Raw notes -> Summary -> Compressed summary -> Archive`

## Rules

- Do not archive large notes directly if a compact summary or compressed summary would preserve their practical value.
- Compress before archiving when the note still carries reusable meaning.
- Keep parent links so compressed knowledge can expand back to richer sources when needed.

## Compression Candidates

Typical candidates:

- large inventories used only occasionally
- long implementation notes with a small number of lasting insights
- duplicated or partially overlapping subsystem notes

## Non-Candidates

Do not compress away:

- critical operating procedures
- active decision records
- the only surviving explanation for a complex behavior
